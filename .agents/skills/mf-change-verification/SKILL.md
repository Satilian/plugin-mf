# Проверка изменения

Прочитать AGENTS.md и определить затронутые публичные входы и потребителей.

1. Выполнить pnpm check. При ошибке установить причину и повторить затронутую проверку после исправления.
2. При изменении сборки или runtime выполнить pnpm start. Команда ждёт HTTP-манифесты зависимостей перед сборкой потребителей; не заменять readiness фиксированной задержкой.
3. Проверить http://localhost:3000: HTML SSR содержит ожидаемые компоненты и mf-releases; браузер после гидрации работает без новых ошибок, remote JS/CSS загружаются из выбранных релизов. Использовать Playwright MCP, если доступен.
4. При изменении релизов проверить новый запрос после пересборки provider и страницу с ранее выбранной версией; при изменении кеша — конкурентные загрузки, повторное использование и сохранение активных leases при clearCache.
5. Проверить exports и декларации собранного пакета; browser-граф не должен включать Node, TypeScript или Rsbuild.
6. Проверить git diff --check и отсутствие посторонних изменений. Не добавлять тесты без запроса; для дополнительных сценариев использовать временные файлы внутри игнорируемого рабочего каталога.

В отчёте отдельно указать выполненные команды, результаты runtime/UI и непроверенные сценарии. Наличие MCP-конфига не считать подтверждением доступности tools. Останавливать только процессы, запущенные для этой проверки.
