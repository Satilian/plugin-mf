# Разработка плагина

Сначала прочитать корневой AGENTS.md и затронутые конфигурации example.

- Проследить путь от hook в build/plugin до выходного артефакта. setup подключает этапы, build-release координирует релиз.
- Проверять API hooks по локальным типам @rsbuild/core и официальной документации соответствующей версии. Context7 использовать адресно, если его tools доступны.
- Не переносить Node или сборочные зависимости в protocol, transport либо браузерный runtime.
- Один releaseId объединяет server/client/types. Публиковать manifest.json только после успешной генерации всех артефактов; сохранять предыдущие неизменяемые каталоги и pointer.json для rollback.
- Генерируемые bootstrap и resolver модули импортируют только публичные входы plugin-mf. Проверять их после сборки потребителя, а не только библиотеки.
- Пути типов вычислять от rootPath Rsbuild. Синхронизация использует контракт protocol/type-manifest, а не реализацию генератора.
- Проверки выбирать по mf-change-verification; функциональные задачи брать из IMPROVEMENT_PLAN.md только в пределах запроса.
